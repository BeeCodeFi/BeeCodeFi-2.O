# Comments & HTML Entities/Special Characters

## HTML Comments {#html-comments}

```html
<!-- This is a comment, not shown to the user -->
```

- Not rendered by the browser, but visible in page source — never put sensitive info in comments.
- Cannot be nested.
- Useful for notes to your future self, temporarily disabling code, or marking sections (`<!-- Header -->`, `<!-- End Header -->`).

## Why Entities Exist {#why-entities-exist}

Certain characters are **reserved** in HTML because the parser uses them for markup itself — most importantly `<` and `>` (tag delimiters) and `&` (starts an entity/character reference). If you type these literally as content, the browser may misinterpret them as markup. Character references let you safely represent them, along with characters not on a standard keyboard (©, emoji-adjacent symbols, non-breaking spaces).

## The Anatomy of a Character Reference {#character-reference-anatomy}

Format: `&name;` (named) or `&#number;` / `&#xHEX;` (numeric), always starting with `&` and ending with `;`.

| Character | Entity Name | Numeric |
|---|---|---|
| `<` | `&lt;` | `&#60;` |
| `>` | `&gt;` | `&#62;` |
| `&` | `&amp;` | `&#38;` |
| `"` | `&quot;` | `&#34;` |
| `'` | `&apos;` | `&#39;` |
| (non-breaking space) | `&nbsp;` | `&#160;` |
| © | `&copy;` | `&#169;` |

## The Three "Always Escape These" Characters {#always-escape}

`<`, `>`, and `&` are the ones that *must* be escaped when they appear as literal content (not markup), since they have structural meaning to the parser.

## Case Sensitivity {#case-sensitivity}

Named references are case-sensitive — `&Amp;` is not the same as `&amp;` and may not resolve correctly.

## Common Misconceptions {#common-misconceptions}

- Forgetting entities are **case-sensitive**.
- Using multiple literal spaces expecting them to render — browsers collapse whitespace to a single space; `&nbsp;` is needed to force extra space (more in Topic 13).
- Assuming comments are hidden from users entirely — they're invisible on the rendered page but fully visible in "View Source."

**Summary in 5 lines:**

- Comments (`<!-- -->`) aren't rendered but are visible in source — don't hide secrets there.
- Reserved characters (`<`, `>`, `&`) must be escaped via character references.
- References come in named (`&lt;`) or numeric (`&#60;` / `&#x3C;`) form.
- Entity names are case-sensitive.
- `&nbsp;` forces a non-breaking space where normal whitespace would collapse.
