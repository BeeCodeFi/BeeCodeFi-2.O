# Document Structure (`<!DOCTYPE>`, `<html>`, `<head>`, `<body>`)

## The Doctype {#the-doctype}

Every HTML document starts with `<!DOCTYPE html>`. This tells the browser to render in **standards mode** rather than "quirks mode" (a legacy compatibility mode that mimics old, non-standard browser behavior). It is *not* an HTML tag/element — it's a special instruction with no closing tag.

```html
<!DOCTYPE html>
```

## The Root Element: `<html>` {#the-root-element}

Everything else lives inside `<html>...</html>`. Best practice: include a `lang` attribute (covered fully in Topic 6), e.g. `<html lang="en">`.

## `<head>` — Machine-Readable Metadata {#head-metadata}

Contains information *about* the document, not displayed directly on the page: `<title>`, `<meta>` tags, links to CSS, favicons, etc. (Deep dive in Topic 31.)

## `<body>` — Visible Content {#body-visible-content}

Contains everything the user actually sees/interacts with: text, images, forms, etc. There should be exactly **one** `<body>` per document.

## Minimal Valid Structure {#minimal-valid-structure}

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <title>Page Title</title>
</head>
<body>
  <p>Hello world</p>
</body>
</html>
```

## Common Misconceptions {#common-misconceptions}

- Thinking `<!DOCTYPE html>` is an HTML tag with a closing tag — it isn't.
- Putting visible content inside `<head>` — browsers will often silently move it to `<body>` or ignore it; don't rely on that.
- Forgetting `<!DOCTYPE html>` triggers **quirks mode**, causing inconsistent rendering/box-model behavior across browsers.

**Summary in 5 lines:**

- `<!DOCTYPE html>` triggers standards mode rendering.
- `<html>` is the root element wrapping the whole document.
- `<head>` holds metadata (not visible content).
- `<body>` holds all visible/interactive content — only one per page.
- Skipping the doctype risks inconsistent, legacy "quirks mode" rendering.
