# 🗺️ What HTML Is & How the Web Works

## 🧱 What HTML Actually Is {#what-is-html}

**<span style="color: #3b82f6;">HTML</span> (HyperText Markup Language)** is **<span style="color: #ef4444;">not a programming language</span>** — it's a *<span style="color: #10b981;">markup language</span>*. Its job is to tell the browser how to **<span style="color: #f59e0b;">structure</span>** content: what's a heading, what's a paragraph, what's a link, what's an image. It describes *meaning and structure*, not visual appearance. HTML is a markup language that tells web browsers how to structure the web pages you visit, and it can be as complicated or as simple as the developer wants it to be.

Think of it like the skeleton of a body:
- **<span style="color: #3b82f6;">HTML</span>** = skeleton/structure (bones — what goes where, what each part *is*)
- **<span style="color: #ec4899;">CSS</span>** = skin and clothes (visual styling — colors, fonts, layout)
- **<span style="color: #f59e0b;">JavaScript</span>** = muscles and nervous system (behavior — interactivity, logic)

HTML deliberately stays out of the styling business. HTML only describes the meaning of the content, not style and formatting — appearance and layout should be defined with CSS, not explicit presentational HTML.

## 📜 A Little History {#client-server-and-requests}

HTML traces back to the late 1980s, when <span style="color: #8b5cf6; font-weight: bold;">Tim Berners-Lee</span> — then a contractor at CERN — devised a way for scientists to share documents over the internet, at a time when internet communication was largely limited to plain text via email, FTP, and Usenet. HTML made it possible to link documents together and embed richer content like formatted text and images.

## 🏛️ Who Governs the HTML Standard {#how-browsers-render-html}

Two bodies matter here:
- **<span style="color: #14b8a6;">WHATWG</span>** (Web Hypertext Application Technology Working Group) — maintains the **HTML Living Standard**, a continuously updated spec.
- **<span style="color: #6366f1;">W3C</span>** (World Wide Web Consortium) — historically published periodic "snapshot" versions.

The WHATWG treats HTML as a constantly evolving "living standard," while the W3C has worked on both HTML's evolution and periodic snapshots of it. In modern practice (and for this course), we'll treat the **WHATWG Living Standard** as the authoritative, current source of truth — it's what browsers actually implement against today.

## 🛠️ What HTML Does — Core Jobs {#the-dom}

HTML has three main responsibilities:
- **<span style="color: #ec4899;">Give text meaning (semantics)</span>** — telling the browser *what* a piece of content is (a heading? a list? a quote?), not just how it looks.
- **<span style="color: #f59e0b;">Structure a document into logical sections</span>** — header, navigation, main content, footer, etc.
- **<span style="color: #14b8a6;">Embed content</span>** — images, video, audio, and other media into a page.

One of HTML's main jobs is to give text meaning — also known as semantics — so that the browser knows how to display and interpret it correctly.

## 🌐 How the Web Actually Works {#urls-and-links-preview}

Simplified flow when you visit a webpage:
- You type a URL / click a link → browser sends a **<span style="color: #ef4444;">request</span>** to a server.
- Server sends back an **<span style="color: #3b82f6;">HTML file</span>** (plus linked CSS/JS/images).
- The browser reads the HTML on the client side to display the page.
- Browser builds the **<span style="color: #f43f5e;">DOM</span>** (Document Object Model) — an in-memory tree representation of the HTML — then applies CSS for styling and runs JS for behavior, and paints the final result on screen.

You don't need to memorize DOM internals yet — just know: **HTML in → browser parses it → structured page out.**

## ❌ Common Misconceptions {#common-misconceptions}

| Misconception | Reality |
|---|---|
| "HTML is a programming language" | It's a *markup* language — no loops, conditionals, or logic. It only describes structure. |
| "HTML controls how things look" | That's CSS's job. HTML *can* technically do minor styling (legacy attributes), but it's bad practice — flagged later in Module 4, Topic 22. |
| "You need HTML5 specifically to write valid HTML" | HTML5 is the current major spec era, but "HTML" as a term generally now just means "whatever the Living Standard currently says." |
| "Browsers all render HTML identically" | Mostly true for standard elements, but rendering can have subtle engine differences (Chromium vs Firefox vs Safari) — a reason validation/testing matters (Topic 41). |

**Summary in 5 lines:**

- HTML is a **<span style="color: #10b981;">markup language</span>**, not a programming language — it structures content, it doesn't program logic or control visual style.
- HTML + CSS + JS form the three pillars of the web: <span style="color: #3b82f6;">structure</span>, <span style="color: #ec4899;">style</span>, <span style="color: #f59e0b;">behavior</span>.
- HTML originated at CERN in the late 1980s (Tim Berners-Lee) to let scientists share linked documents.
- The **<span style="color: #14b8a6;">WHATWG Living Standard</span>** is the current, evolving authoritative spec browsers implement against.
- HTML's core jobs: give content **<span style="color: #ec4899;">semantic meaning</span>**, **<span style="color: #f59e0b;">structure</span>** documents, and **<span style="color: #14b8a6;">embed</span>** media.
